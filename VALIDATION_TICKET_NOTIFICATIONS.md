# Проверка обновления уведомлений

## Исполнено в этом окружении

Python 3.13.5, SQLAlchemy 2.0.50, SQLite.

```text
python -m compileall -q bot tests
python -m unittest tests.offline_mentor_checks tests.offline_session_checks tests.offline_ticket_notification_checks -v
```

**106 проверок: OK.** Из них 62 прежние проверки, 36 новых проверок ядра очереди
и 8 проверок транспортной функции. Вывод: `validation/ticket-notifications-tests.txt`.

В проверках БД используется настоящий SQLite/SQLAlchemy; синхронный адаптер заменяет
только границу async-драйвера. Проверены маршрутизация, создание тикета и очереди
одной транзакцией, откат при сбое, уникальность задания, обработка временной ошибки,
интервалы повтора, запрет повтора успешно доставленных заданий, резервирование,
повторное получение задания после истечения срока, два конкурирующих обработчика,
удаление прав через БД, restricted-тикеты, массовая доставка и совместимость миграции.

Для 8 транспортных тестов из исходного `bot/notify.py` компилируется только функция
`_send_new_ticket`; подставляются транспорт, классы ошибок и представления. Проверены
флаги отправки, кнопка и fallback, но это **не** запуск aiogram и **не** проверка
реального Telegram API. Проверка схемы PostgreSQL ограничена компиляцией DDL,
реального PostgreSQL-соединения не было.

## Не исполнено

```text
python -m pytest -q
```

Полный прогон остановлен на загрузке conftest: `ModuleNotFoundError: No module named
'aiogram'`. Попытка установить `requirements-dev.txt` не удалась из-за недоступного
сетевого доступа к реестру пакетов. В этой среде также нет asyncpg и aiosqlite.
Зависимости проекта оставлены без изменений: aiogram 3.31.0 и SQLAlchemy 2.0.54;
локальные проверки ядра исполнены на доступной версии SQLAlchemy, указанной выше.

Вывод неудачного запуска: `validation/ticket-notifications-dispatcher-attempt.txt`.
8 новых тестов Dispatcher включены в архив, но здесь не запускались. Старые файлы
VALIDATION_MENTORING.md и VALIDATION_MENTORS.md описывают предыдущие версии, а не
новые результаты этого обновления.

Не проверены: настоящий Telegram, настоящая БД PostgreSQL, Railway, сборка Docker
и установка зафиксированных зависимостей. Рабочий сервис пользователя не изменялся.

## Воспроизведение полной проверки

В отдельном тестовом окружении:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Только для **отдельной одноразовой тестовой БД**, не рабочей:

```bash
TEST_DATABASE_URL=postgresql://user:password@localhost/hm_test python -m pytest -q
```

**Важно:** фикстура тестов очищает таблицы указанной БД между тестами. Никогда не
задавайте рабочую DATABASE_URL в TEST_DATABASE_URL.

После запуска выполните ручной сценарий из TICKET_NOTIFICATIONS_GUIDE.md с тестовым
ботом: /testnotify, обычное обращение, жалоба на координатора, анонимное обращение
и открытие карточки по кнопке.
