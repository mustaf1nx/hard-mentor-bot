# Изменения: слайсы 0–1 — триместр, роли по предметам, строгий входной билет

Основа — `context/10-bot-spec.md` (согласованная спецификация). Реализованы слайсы 0 и 1.

## Что сделано

### Слайс 0 — Alembic

- `alembic.ini`, `migrations/env.py` (асинхронный движок, те же модели, что у бота).
- `0001_baseline` — пустая ревизия: действующая база создавалась через `create_all`, её достаточно отметить `alembic stamp 0001`.
- `create_all` в `init_db()` остаётся — на нём работают тесты и первый запуск. Alembic ведёт только последующие изменения.

### Слайс 1 — соответствие Положению

- **Триместр (п. 8.1.5).** Таблица `terms`: название, понедельник старта, число недель. Дата старта обязана быть понедельником.
- **Роль на предмет (п. 5.9).** Таблица `mentor_roles`: ментор + предмет + триместр → Ведущий / Респондент / Автор. Один человек может держать разные роли по разным предметам.
- **Строгий входной билет (п. 8.1.4, Прил. 5).** Запись теперь три шага: «в чём затруднение» (≥20 символов) → «что уже пробовали» (≥30 символов, «ничего»/«не знаю» не принимаются) → самооценка 1–5 кнопками. Вопрос и попытки хранятся в `session_bookings.tried` и `.self_rating`.
- **Автоотказ (п. 8.1.4).** «объясните всё с нуля», «сделайте/решите за меня», «скиньте готовое/решение» отклоняются с объяснением. Это правила, не LLM: Положение называет именно эти формулировки.
- **Запись закрывается за 24 часа** до начала слота (п. 8.1.4).
- **Автоотмена слота (п. 8.1.3).** Раз в минуту вместе с циклом напоминаний: если до старта меньше 24 часов и активных записей меньше двух — слот аннулируется с уведомлением ведущего и записавшихся. Недели 5, 9, 10 исключены. Если триместр не задан, автоотмена **не** выполняется — лучше не отменить ничего, чем снести пиковую неделю.
- **`/term`** — задать триместр и посмотреть текущую неделю; **`/role`** — назначить роль по предмету (принимает `@ник` или id, русские названия ролей); **`/roles`** — сводка ролей по триместру.

## Новые таблицы и колонки

Таблицы: `terms`, `mentor_roles`.
Колонки: `session_bookings.tried`, `session_bookings.self_rating`, `mentoring_sessions.term_id`.

Деструктивных изменений нет. `users`, `mentors`, `tickets`, `notes`, `meta` не затрагиваются.

## Порядок на проде

```bash
pip install alembic          # добавлен в requirements-dev.txt
alembic stamp 0001           # один раз: отметить текущую схему
alembic upgrade head         # применить слайс 1
```

Ревизия `0002` идемпотентна: проверяет наличие таблиц и колонок, поэтому безопасна и на базе, где схема уже создана `create_all`.
