## Alembic — проверено

`tools/check_migrations.py` прогоняет четыре сценария, все проходят:

```
[1] Пустая база -> upgrade head
  OK   upgrade прошёл / таблица terms создана / таблица mentor_roles создана / ревизия 0002
[2] Старая схема (как в проде) -> stamp 0001 -> upgrade head
  OK   stamp 0001 / колонок ticket ещё нет / upgrade прошёл
  OK   session_bookings.tried / .self_rating / mentoring_sessions.term_id добавлены
[3] Повторный upgrade head — ничего не ломается, ревизия всё ещё 0002
[4] Схема создана create_all (так живут тесты) -> upgrade head — колонки на месте
```

Сценарий 2 — ровно наш путь на проде: старая схема, `stamp 0001`, затем `upgrade head`.
Сценарий 4 доказывает, что ревизия не конфликтует с `create_all`, на котором работают тесты.

### Кодировка alembic.ini

`alembic.ini` намеренно оставлен ASCII-only. Alembic читает его через
`compat.read_config_parser(..., encoding="locale")`, а на Windows это cp1252 —
русские комментарии дают `UnicodeDecodeError: 'charmap' codec can't decode byte 0x81`.
Проверено: `PYTHONUTF8=1` не помогает, `locale.getencoding()` остаётся `cp1252`
даже при `sys.flags.utf8_mode == 1`.

Русские пояснения поэтому живут в `CHANGES_SLICE1.md` и `context/10-bot-spec.md`.
Остальные файлы проекта — UTF-8 без BOM.

## Что НЕ проверено

- **Живой Telegram.** Токена в `.env` нет, сеть закрыта. Ручная проверка: `BOT_TOKEN` в `.env`,
  `python -m bot`, пройти три шага билета и `/term`.
- **Postgres.** Тесты и миграции шли на SQLite. Для Postgres: `TEST_DATABASE_URL=... pytest`,
  и `alembic upgrade head` на копии боевой базы.
