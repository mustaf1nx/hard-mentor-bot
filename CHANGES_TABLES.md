# Таблицы в Telegram: нативных нет, сделали `<pre>`

## Что проверил

Установлен aiogram 3.31.0, он собирается под **Bot API 10.3**. Список сущностей форматирования,
который библиотека знает (`MessageEntity.type`), полный:

```
mention, hashtag, cashtag, bot_command, url, email, phone_number,
bold, italic, underline, strikethrough, spoiler, blockquote,
expandable_blockquote, code, pre, text_link, text_mention, custom_emoji, date_time
```

**Сущности «таблица» там нет.** Поиск по всему пакету aiogram упоминаний `table` не находит
(кроме high score в Bot API). Значит `sendMessage` с таблицей отправить нельзя — бот физически
не может, что бы ни было в клиенте.

## Что сделано вместо

`bot/tableview.py` — таблицы в `<pre>`. Telegram рисует `pre` как блок моноширинным шрифтом,
и колонки в нём выравниваются по-настоящему, а не «на глаз».

```
Предмет       м с п о б
------------- ---------
Calculus 1    · ✓ ✓ · ·
Discrete Math · · · · ·
```

Правила модуля:

- **ширина до 34 символов** — шире на телефоне Telegram переносит строки и выравнивание рвётся;
- длинные названия обрезаются с `…`, а не ломают таблицу;
- содержимое экранируется, чтобы HTML внутри ячеек не превращался в разметку;
- колонки-галочки не сжимаются при нехватке места;
- `✓` / `·` вместо эмодзи: эмодзи в моноширинном блоке занимают непредсказуемую ширину.

## Где применено

Пока только в разрезе «Цикл по предметам» — там была самая нечитаемая строка из галочек и
прочерков. Остальные экраны читаются строчками и таблицы не требуют.

## Рендер

`tools/render_chat.py` теперь рисует `<pre>` моноширинным (Consolas), как Telegram, и не выводит
сами теги. По ходу поймал баг: `re.split` возвращает разделители, и `<pre>` попадал в текст
картинки — теги были видны. Теперь они отбрасываются.
