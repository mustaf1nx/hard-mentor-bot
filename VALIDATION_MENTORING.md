# Проверка версии с менторками

## Выполнено в среде подготовки архива

```text
python -m compileall -q bot tests
python -m unittest tests.offline_mentor_checks tests.offline_session_checks -v

Ran 62 tests
OK
```

18 проверок прежнего управления менторами + 44 проверки нового ядра.
Полный вывод: `validation/core-tests.txt`.

Проверки выполнялись с реальными моделями SQLAlchemy и SQLite с включёнными внешними ключами.
Тонкий адаптер заменяет только асинхронную границу драйвера синхронной сессией; запросы,
ограничения БД, миграция, проверки прав, правила занятий и решения по уведомлениям — из рабочего кода.
Ни Telegram, ни Railway при этих проверках не использовались.

Покрыты создание и повторное подтверждение, нормализация предметов/тем, права координатора,
уникальность записей, запись без подготовительных материалов, сохранение и изменение ответов,
защита чужих чек-листов, неизменяемость исторических пунктов, подсчёт пропусков,
посещаемость, завершение, ручная отмена, перенос, замена и удаление ведущего,
открытые/закрытые файлы, автозаполнение темы, ограничения файлов, сводка и повторный запуск схемы.
Проверяются решения о подавлении/создании напоминаний и компиляция нового DDL для PostgreSQL.

## Что не выполнено

Полный `pytest -q` остановился при загрузке `tests/conftest.py`:

```text
ModuleNotFoundError: No module named 'aiogram'
```

Попытка установить `requirements-dev.txt` не удалась из-за отсутствия сетевого доступа
к индексу пакетов. `asyncpg` и `aiosqlite` также не были доступны. Локально установлен
SQLAlchemy 2.0.50; проект сохраняет исходный pin 2.0.54. Производственные версии зависимостей
в `requirements.txt` не менялись ради прохождения тестов.

`tests/test_sessions.py` добавлен, но сквозные сценарии диспетчера в этой среде не запускались.
Старые сквозные `test_flows.py`, `test_mentors.py` здесь также не запускались.
Реальная PostgreSQL, row-lock concurrency, Telegram API, загрузки документов и deployment
Railway не проверялись. Компиляция SQL для PostgreSQL не равна запуску SQL на PostgreSQL.
Результат не следует описывать как «всё протестировано на Railway».

## Как выполнить полный прогон

В отдельном окружении, не в рабочей базе:

```bash
python -m venv .venv
# Активируйте .venv средствами вашей ОС.
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

По умолчанию тесты диспетчера работают на SQLite в памяти с подменой Telegram-транспорта.
Для PostgreSQL настройте `TEST_DATABASE_URL` только на отдельную тестовую базу, например:

```bash
TEST_DATABASE_URL=postgresql://test_user:test_password@localhost/test_hard_mentor python -m pytest -q
```

**Нельзя использовать рабочую базу:** существующая тестовая fixture очищает таблицы
между тестами. Не запускайте этот прогон с производственным `TEST_DATABASE_URL`.
Для реального Telegram используйте отдельный тестовый токен, чтобы не конфликтовать
с рабочим polling-процессом. Сценарий ручной проверки находится в `MENTORING_GUIDE.md`.
