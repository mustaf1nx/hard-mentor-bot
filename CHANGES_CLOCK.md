# Блок 2: виртуальные часы

## Зачем

Две проблемы, обе про время:

1. **Тесты зависели от реальных часов.** Проверка «за 3 дня до конца триместра» ломалась,
   если прогон попадал на границу суток: тест строил даты от UTC, а бот считает недели
   в `Asia/Almaty`. Уже ловили ложное падение в час ночи.
2. **Автоотмену проверяли ожиданием.** Сценарий `autocancel` спал 75 секунд, дожидаясь
   фонового цикла, который просыпается раз в минуту.

## Что сделано

### `bot/clock.py`

Единственный источник «сейчас» для доменной логики:

```python
from bot import clock

clock.freeze(datetime(2026, 11, 7, 10, 0))   # заморозить
clock.travel(timedelta(hours=10))            # сдвинуть
clock.reset()                                # вернуть реальное время
```

В проде провайдер не задан — работает обычное время. Переведены `service.py` (22 вызова),
`reminders.py`, `mentoring/ui.py`, `dashboard.py` и обработчики итогового отчёта.

### Настраиваемый интервал циклов

`Settings.reminder_interval` (env `REMINDER_INTERVAL`, по умолчанию 60 с). В сценарии
автоотмены выставляется 2 секунды.

Сценарии теперь могут задавать переменные окружения:

```json
{ "env": { "REMINDER_INTERVAL": "2" } }
```

| Сценарий `autocancel` | 90 с | **30 с** |

Новые тесты `tests/test_clock.py`:

- слот с одной записью отменяется сразу, без ожидания, и запись не теряется;
- слот с двумя записями остаётся;
- пока до начала больше суток — не отменяется, после сдвига времени на 10 часов — отменяется.

## Замечание

Остальные модули (`repo.py`, `views.py`, `reports.py`, `ticket_notifications.py`) всё ещё
считают время напрямую. На их тесты это не влияет — они и так передают `now` явно, — но если
понадобится заморозить время для сценариев с SLA, их тоже стоит перевести на `clock`.
