# Postgres: прогон на реальном диалекте

Блок 3 плана. До этого все 127 тестов шли на SQLite, где **внешние ключи не проверяются,
а `with_for_update` — пустышка**. То есть логика блокировок при записи на слот не проверялась
вообще, хотя в проде именно она решает гонку.

## Как запускать

```powershell
docker run -d --name hm-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=hm -p 55432:5432 postgres:16
$env:TEST_DATABASE_URL="postgresql://postgres:postgres@localhost:55432/hm"
.venv\Scripts\python.exe -m pytest -q
```

Остановить: `docker rm -f hm-pg`.

## Что сломалось на первом прогоне: 85 падений из 127

### 1. Каждый тест жил в своём event loop

`RuntimeError: got Future attached to a different loop`. Движок создаётся в сессионной
фикстуре, а тесты по умолчанию получали функциональный цикл. `aiosqlite` это терпит
(работает в своём потоке), `asyncpg` привязывает соединение к циклу и падает.

Лечение — одна строка в `pytest.ini`:

```ini
asyncio_default_test_loop_scope = session
```

### 2. SQLite молча разрешал записи от несуществующих пользователей

`ForeignKeyViolationError: Key (student_id)=(1001) is not present in table "users"`.

Тесты создавали `Viewer` для ALICE и писали запись на слот, не создавая строку в `users` —
в SQLite это проходило, в Postgres нет. Добавлен помощник `ensure_users(session, *uids)`
в `tests/conftest.py`; он вызывается только там, где запись создаётся в обход чата
(через чат пользователя создаёт мидлварь).

Побочная ловушка: сначала я создал ALICE и BOB прямо в фикстуре — и сломал
`test_english_user_gets_english`, потому что у существующего пользователя язык уже
зафиксирован и первый контакт на английском перестаёт работать. Поэтому — точечно.

### 3. Захардкоженный `term_id = 1`

В тесте пагинации KPI роль привязывалась к триместру с id 1. В SQLite последовательность
начинается с единицы, в Postgres — нет. Заменено на `term.id` после `flush()`.

## Что появилось благодаря Postgres

`tests/test_concurrency.py` — два теста, которые на SQLite пропускаются:

| Тест | Что доказывает |
|---|---|
| Две одновременные записи одного студента | `with_for_update` сериализует: создаётся **одна** запись, а не две |
| Две одновременные записи разных студентов | никто не теряется: обе записи активны |

## Итог

| Прогон | Результат |
|---|---|
| SQLite | 127 passed, **2 skipped** (гонки — только для Postgres) |
| Postgres | **129 passed** |

Теперь блокировки, уникальность и внешние ключи проверяются на том же диалекте, что в проде.

## Замечание на будущее

CI должен гонять **оба** варианта: SQLite — быстро на каждый коммит, Postgres — на ветку
перед мержем. Иначе такие расхождения снова накопятся незаметно.
