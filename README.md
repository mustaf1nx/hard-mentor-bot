# Бот для заявок на хард-ментора

Собирает от студентов заявки «нужен хард-ментор по предмету X» через Telegram
и показывает их в веб-админке, где куратор вручную назначает ментора.

## Структура

```
main.py              # Точка входа: запускает бота и админку вместе
bot.py                # Telegram-бот (принимает заявки)
admin_app.py           # Веб-админка (FastAPI)
database.py             # Модель БД (Postgres/SQLite через SQLAlchemy)
templates/
└── admin.html           # Страница админки
requirements.txt
```

Все файлы должны лежать в корне репозитория (кроме `admin.html`, который
остаётся внутри `templates/`) — именно так их ищет Railway.

Бот и админка работают в **одном процессе** (через `main.py`). База — Postgres
(через `DATABASE_URL`), локально без Postgres под рукой всё падает в
SQLite-файл `mentors.db`.

## Установка

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Переменные окружения

- `BOT_TOKEN` — токен бота от @BotFather (`/newbot` в Telegram).
- `DATABASE_URL` — строка подключения к Postgres. Локально можно не задавать
  — тогда используется SQLite.

```bash
export BOT_TOKEN="123456:ABC-ваш-токен"
```

## Запуск

```bash
python main.py
```

Поднимет и бота, и админку сразу. Админка — на http://localhost:8000, там
список заявок с фильтром по статусу (новая / в работе / закрыта), полем для
имени ментора и кнопкой «Сохранить». Когда заявку переводят в «закрыта» с
указанным ментором, студенту автоматически приходит сообщение в Telegram.

## Как это работает для студента

1. `/start` в боте.
2. Бот по очереди спрашивает: ФИО → курс → предмет → комментарий.
3. Заявка сохраняется в базу со статусом «новая».
4. Куратор видит её в админке и либо сразу назначает ментора, либо переводит
   в «в работе», пока ищет подходящего человека.

## Деплой на Railway

1. Залейте `main.py`, `bot.py`, `admin_app.py`, `database.py`,
   `requirements.txt` и папку `templates/` в корень GitHub-репозитория.
2. **New Project → Deploy from GitHub repo**, выберите репозиторий — один
   сервис на весь проект.
3. В том же проекте: **+ New → Database → Add PostgreSQL**.
4. В сервисе с кодом (**Variables**):
   - `BOT_TOKEN` = токен от @BotFather
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}` (выбирается из списка,
     вручную вписывать не нужно)
5. **Settings → Deploy → Start Command**: `python main.py`
   (важно — по умолчанию Railway пытается запустить `uvicorn main:app`,
   а у нас `main.py` не ASGI-приложение, а обычный скрипт, который сам
   поднимает и бота, и uvicorn внутри).
6. Redeploy.

## Что можно добавить дальше (если понадобится)

- Список предметов кнопками вместо свободного текста — меньше опечаток и
  проще группировать одинаковые заявки.
- Роль «ментор»: менторы сами регистрируются в боте и указывают предметы,
  а админка подсказывает подходящих кандидатов вместо ручного ввода имени.
- Уведомление в чат кураторов (например, в Telegram-группу) при каждой новой
  заявке, чтобы не проверять админку вручную.
