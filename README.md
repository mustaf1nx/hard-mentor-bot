# Бот для заявок на хард-ментора

Собирает от студентов заявки «нужен хард-ментор по предмету X» через Telegram
и показывает их в веб-админке, где куратор вручную назначает ментора.

## Структура

```
hard_mentor_bot/
├── bot.py            # Telegram-бот (принимает заявки)
├── admin_app.py       # Веб-админка (FastAPI)
├── database.py         # Общая модель БД (SQLite)
├── templates/
│   └── admin.html       # Страница админки
└── requirements.txt
```

Бот и админка — два независимых процесса, которые используют одну и ту же
SQLite-базу `mentors.db` (создаётся автоматически при первом запуске).

## Установка

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Токен бота

1. Напишите @BotFather в Telegram, создайте бота (`/newbot`), получите токен.
2. Задайте переменную окружения перед запуском обоих процессов:

```bash
export BOT_TOKEN="123456:ABC-ваш-токен"
```

(в Windows PowerShell: `$env:BOT_TOKEN="123456:ABC-ваш-токен"`)

## Запуск

В одном терминале — бот:

```bash
python bot.py
```

В другом — админка:

```bash
python admin_app.py
```

Админка откроется на http://localhost:8000 — там список заявок с фильтром по
статусу (новая / в работе / закрыта), полем для имени ментора и кнопкой
«Сохранить». Когда заявку переводят в статус «закрыта» с указанным ментором,
студенту автоматически приходит сообщение в Telegram с именем ментора.

## Как это работает для студента

1. `/start` в боте.
2. Бот по очереди спрашивает: ФИО → курс → предмет → комментарий.
3. Заявка сохраняется в базу со статусом «новая».
4. Куратор видит её в админке и либо сразу назначает ментора, либо переводит
   в «в работе», пока ищет подходящего человека.

## Что можно добавить дальше (если понадобится)

- Список предметов кнопками вместо свободного текста — меньше опечаток и
  проще группировать одинаковые заявки.
- Роль «ментор»: менторы сами регистрируются в боте и указывают предметы,
  а админка подсказывает подходящих кандидатов вместо ручного ввода имени.
- Уведомление в чат кураторов (например, в Telegram-группу) при каждой новой
  заявке, чтобы не проверять админку вручную.
- Переход с SQLite на PostgreSQL, если заявок станет много одновременно.
